# 运行与恢复

生产启动前构建 `go build -o atlas ./cmd/atlas`。通过ATLAS_STATE指定独立可写状态路径，通过ATLAS_ADDR指定受信环境的监听地址。状态目录应由运行进程拥有；临时写文件与最终文件位于同一个目录。

同一状态路径的第二个进程会因为独占文件锁拒绝启动。锁文件可长期存在，锁的有效性由操作系统进程锁决定。不要通过删除锁文件启动第二个写进程。

SIGTERM或中断信号会停止领取任务，取消执行中的计算，等待HTTP请求和执行循环结束。执行中的任务保留running，下一次启动会重新入队。SIGKILL恢复用 `python3 scripts/walkthrough.py --workflow recover-render` 演练；只会结束该脚本自己启动的实例。

备份时先正常停止实例，复制状态JSON；恢复时向空的独立状态路径复制，再启动。不要把运行中手工编辑过的JSON直接作为新事实。启动校验拒绝不支持版本、损坏摘要、孤立关联和非法文档。备份包含PNG字节与全部快照引用闭包，无需从外部素材服务恢复。

容量观察入口是GET /v1/status。它报告未压缩的持久结果PNG字节总量和各任务状态数量，不代表堆内存峰值。完整状态在事务中复制并编码，因此长期积累会增加提交成本。当前未提供任务或快照删除；部署应按预期数据量规划状态盘和实例周期。结果清理入口仅删除PNG字节。历史事件超过500条会截断，但sequence继续增加。

## 状态盘空间保护

所有持久写入都落在 `ATLAS_STATE` 所在文件系统。进程通过 `statfs` 持续探测该目录的可用字节和可用 inode，并在每次提交事务前比对预留水位：可用字节低于 `ATLAS_DISK_MARGIN_BYTES`（默认 64 MiB）或可用 inode 低于 `ATLAS_DISK_MARGIN_INODES`（默认 128）时，磁盘守卫判定不可写。实际写入若返回 ENOSPC/EDQUOT（与探测存在竞态），同样归类为空间故障并立即刷新守卫结论。

空间不足时的确定性行为：

- 所有需要落盘的入口（场景、素材、快照、导入、任务提交/取消/重试、撤回、退役）返回 503，JSON `code` 为 `disk_full`，并带 `Retry-After: 30`。守卫在业务变更之前运行，因此不会出现“已接受却无法持久”的任务、幂等收据或快照；失败事务不改动内存状态，旧状态继续可读。
- 只读入口保持可用：GET 场景/快照/任务、事件、`/v1/status` 以及结果 PNG 下载（含 304）。POST `/v1/compare` 只解码既有结果，也不受影响。
- 执行器停止领取新任务，避免把任务卡入 running。已经在渲染的任务若在提交结果时遇到空间故障，任务在持久状态中保持 running，内存不写入半成品；空间恢复后执行器的运行时恢复会把这类孤儿 running 任务重新入队，attempt 不增加，沿用固定输入重放。
- `DELETE /v1/artifacts/{id}`（结果清理）走救济写入通道，空间不足时仍然允许：它只缩小状态文件，是释放空间的自助手段。清理后任务仍是 succeeded，结果事实和摘要保留。
- `GET /healthz` 在不可写时返回 503，响应体含 `disk` 详情（可用字节/inode、水位、原因、检查时间）；可写时返回 200 并携带相同结构，供负载均衡和告警使用。`GET /v1/status` 始终包含 `disk` 块。
- 启动时若磁盘已满，进程不退出：以降级模式继续提供只读和诊断服务，启动恢复（running→queued）延迟到可写后由运行时恢复完成。空间恢复后无需重启即可自动恢复全部写入与领取。

配置项（环境变量，部署单元 `deploy/atlas.service` 已内置默认值）：

| 变量 | 默认 | 含义 |
|---|---|---|
| `ATLAS_DISK_MARGIN_BYTES` | 67108864（64 MiB） | 提交所需的最小可用字节，应不小于单次状态文件最大写入量 |
| `ATLAS_DISK_MARGIN_INODES` | 128 | 提交所需的最小可用 inode |
| `ATLAS_FAULT_FULL` | 未设置 | 设为 `1`/`true` 时强制守卫判定不可写，仅用于受控故障演练，禁止在生产启用 |

## 空间故障处置与恢复手册

1. 告警确认：`GET /healthz` 返回 503 或 `/v1/status` 的 `disk.writable=false`；响应中的 `reason` 区分字节不足、inode 不足和卷不可访问。
2. 不要重启进程或删除 `state.json.lock`。降级期间进程继续提供只读服务，重启不会释放空间，反而会中断只读可用性。
3. 释放空间：优先 `DELETE` 可清理的 artifact（见上，救济通道在满盘时可用）；或在挂载层面扩容、清理同卷无关文件。不要手工编辑状态 JSON。
4. 恢复验证：守卫在每个探测周期（亚秒级）自动复查；`GET /healthz` 恢复 200 后，用原幂等键重放失败的任务提交——若故障期间请求从未落盘，会正常入队；若曾经落盘成功，则返回原任务，绝不会因重试生成重复任务或重复收据。
5. 检查事件中的 `job.requeued`，确认曾滞留的 running 任务已重新入队并最终 succeeded；结果摘要可与既有记录比对。

## 损坏状态与空文件保护

启动时若状态文件存在但内容为空/纯空白、JSON 无法解析或校验失败（版本、摘要、孤立关联、非法文档），进程拒绝启动并保留原文件，绝不会以空库覆盖后继续服务。崩溃遗留的 `.atlas-write-*` 临时文件在成功打开后自动清理。处置方式是保留现场，在副本上排查，并按备份流程恢复：先正常停止实例，把备份 JSON 复制到独立的空状态路径再启动。

故障时保留当前状态文件和服务日志，在副本上检查。500表示事务未能完成；客户端可先读取原请求目标确认状态。提交任务时使用稳定幂等键，不能因为连接中断盲目换键。409应结合当前场景revision、快照state或收据语义判断。410说明成功结果字节已清理，任务成功事实仍保留。

`deploy/atlas.service` 是Linux systemd配置示例，需按实际用户、二进制和状态路径调整。macOS可直接运行同一二进制。当前未验证容器部署、跨进程共享写入、跨机器文件系统锁或网络存储。
